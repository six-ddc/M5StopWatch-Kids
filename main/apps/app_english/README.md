# AppEnglish — 看图听音学英语

给幼儿园到小学低年级的英语启蒙，跑在只有两个按键的圆屏手表上。

一组 12 个词，先当图卡过一遍（图 + 真人发音 + 中文），再做 10 道二选一。**不做跟读，不做句子填空**——这个年龄段的全部交互就是看、听、指。

## 为什么全是具象词

这个 app 教一个词的方式是给它一张图。所以**画不出来的词就进不了词表**，这是硬约束不是偏好。

调研时我拿 ARASAAC 图库实测过：`apple / cat / bus / jump / teacher / elephant` 这类具象词命中率 15/15，图还不止一张。但换成 sight words 就崩了——`could` 返回 **0 张**，`because` 2 张且无关，`the` 那 615 条是全文模糊匹配的噪音。

这不是图库的缺陷，是「the / was / could」本来就没有样子。它们的标准教法是在句子里反复遇见直到自动识别，而句子填空这一期不做，所以**那 220 个服务词整体不在范围内**。词表主干因此是同一份分级表里 95 个名词那一类：全是具象词，本来就有图有音。

## 词典自带的图救不了儿童词汇

数据源另一个反直觉的实测结果，值得记下来免得后人重走：

手上那个词典 mdd 里有 **十万余条真人发音 MP3** 和 **一千多张 1000×1000 真实照片**。发音是宝藏，照片不是。

拿 70 个儿童最高频具象词去比对那批配图，**只命中 32 个（46%）**，而且没命中的恰恰是最基础的一批：`sun / star / bus / car / book / ball / hand / eye`。看一眼配图词表的开头就明白了：`abacus / abalone / abbey / absinthe / acacia / albatross`——**成人词典只给「查了也想象不出长什么样」的冷僻词配图**，apple 和 cat 对成人母语者根本不需要图。这套逻辑和儿童学习需求正好相反。

所以分工是：**图片走 [ARASAAC](https://arasaac.org)，音频走本机词典**（70 词实测美音命中 83%）。

### 音频抽取的坑

「美音文件名是 `en_us_<词>.mp3`」这个规律对 55/60 成立，但剩下 5 个词更危险：mdx 词条里给 `blue`、`star`、`milk` 标 `type_us` 的链接，指向的是**同音词的录音**——照抄会读出错的词。

管线因此按**可证伪程度**排优先级：`en_us_<词>.mp3`（文件名自证）→ 词头 pron 块里的纯数字 `type_us` 文件 → `en_gb_<词>.mp3` → 数字 `type_uk` → 警告并静音。文件名和词头对不上的 `en_us_*` 一律不信。480 词里 413 词美音、64 词英音、3 词静音，`manifest.json` 里逐词记了 `file` / `accent` / `picked_by`。

静音那 3 个是 `scared` / `surprised` / `bored`——词典里的词条是 `scare` / `surprise` / `bore`，分词形容词没有独立录音。**不因此删词**：图还在，页面回落到只显示文字。`logic_test` 的断言相应放宽到 98%，低于这个数说明 mdd 整个没读到，而不是又多了一个分词。

## 144 px 是算出来的，不是挑出来的

quiz 页两张图并排，必须落在两个物理按键正下方，且任何一角不能越过 233 px 的可视半径。

| 图片尺寸 | 卡片 | 中心 | 角点距圆心 | 两卡间隙 |
|---|---|---|---|---|
| 160 | 168 | (±88, −95) | **248** ✗ 越界 | 8 px |
| 160 | 168 | (±86, −30) | 205 | **4 px** 太挤 |
| **144** | **152** | **(±84, −40)** | **198** ✓ | **16 px** ✓ |

160 px 放不下——不是差一点，是角点甩出去 15 px。144 是能让两张图都看清的最大值，顺带省了 19% 存储。`tools/english_host_test/sim` 每次都会断言这件事。

## 图片格式：为什么是 I4

固件的 `lv_conf` 里 TJPGD 和 LODEPNG 都开着，但 **host sim 的 `lv_conf.h` 里两个都是 0**。用 JPEG 的话主机测试根本渲染不了图，而这个 app 的核心就是图。

`LV_COLOR_FORMAT_I4`（16 色索引，调色板紧挨着像素）由 LVGL 核心解码，**不依赖任何解码器组件**，所以设备和 sim 渲染路径完全一致。一张 144×144 是 10,432 B（64 B 调色板 + 10,368 B 像素）。对 ARASAAC 那种平涂卡通图，16 色够用。

### 一个只在设备上犯的错

设备 `LV_CACHE_DEF_SIZE = 1 MB`，host sim = 0。页面为每个图片位复用同一个 `lv_image_dsc_t`，如果不显式 `lv_image_cache_drop()`，**sim 上一切正常，设备上会画出上一张图**。这类差异是 sim 结构性看不见的，所以代码里写死了 drop 并注明了原因。

（`lvgl.h` 不包含这个 API，要 `#include <src/misc/cache/lv_cache.h>`。）

## 音频链路

词典里的原始音频是 44.1 kHz 单声道 64 kbps MP3，0.36–0.82 秒。管线降到 **16 kHz IMA ADPCM**：一个词约 8 KB，和原始 MP3 差不多大，但解码只要一百行、零外部组件。语音能量几乎都在 8 kHz 以下，听感无损（实测 SNR 均值 24.2 dB，最差 18.1 dB）。

ES8311 整个固件共用一条 44100 Hz 的流，所以 16 kHz 缓冲直接喂进去会**快 2.76 倍、音高抬高一个五度**。`adpcm::decodeToPlayback()` 边解码边线性插值升采样，一趟出 44.1 kHz。

> 曾经的 off-by-one：插值循环写成 `src_index < whole` 会让输出恒定滞后一个源样本；末尾源耗尽时如果继续按斜率外推，会拖出一声可闻的 tick。两处都在 `logic_test` 里有对应断言。

音量是全局的，定在 `hal_audio.cpp` 的 `kDefaultSpeakerVolume`。**这个 0~100 的刻度不是百分比**：`esp_codec_dev` 的默认曲线把它线性映射到 −50~0 dB，所以它是一个衰减旋钮，92 = **−4 dB**，而原来的 80 是 −10 dB——白扔了 10 dB。留那 4 dB 是给喇叭的余量，录音已经峰值归一化到 0.9 满刻度，开到 100 最响的地方就顶到轨了。

这个常量是唯一事实来源。本固件没有音量 UI，但刷过原版 UserDemo 的设备会在共用的 `system` 命名空间里留下它自己的 `spk_vol`，不主动写回就会被那个陈旧值悄悄盖掉。

## 分层与测试

```
data/eng_data.*   ENG1 blob 读取器      ← 无 LVGL / 无 IDF
data/adpcm.*      ADPCM 解码 + 升采样    ← 无 LVGL / 无 IDF
game/session.*    学习会话状态机         ← 无 LVGL / 无 IDF
view/*.cpp        四个页面（LVGL）
app_english.cpp   状态机 · 音频 · NVS · 反馈节奏
```

前三层不碰 LVGL 和 ESP-IDF，可原生编译：

```bash
cmake -S tools/english_host_test -B build_english && cmake --build build_english
./build_english/english_logic_test              # 10,983 项断言
./build_english/english_sim --out /tmp/engshots # 真 LVGL 渲染 + 越界断言
```

`english_sim` 编译的是**真正的 view .cpp**，喂的是**真正的 blob**，所以：

- 480 个词逐个渲染，检查每张图的点亮率落在 3%–97%（全黑=没画出来，全亮=palette 或 stride 错了）。实测 5%（`scooter`，一根细杆）到 98%（白底卡）
- 每个页面、每种反馈态、完整 10 题回合，断言没有一个亮像素跑出 r=233
- 自动找出**渲染最宽**的单词和中文释义来测极端布局（不是凭字数猜——`motorcycle` 225 px 才是最宽的那个）

## 交互

| | 单元选择 | 图卡 | 答题 | 结果 |
|---|---|---|---|---|
| **A** | 换一组 | 重播发音 | 选左边 | 再来一次 |
| **B** | 开始 | 下一个 | 选右边 | 换一组 |
| **轻触** | 选中/开始 | 重播（整屏任意处） | 选那张图 | 推进 |
| **A+B 长按** | 回主页 | 回单元选择 | 回单元选择 | 回单元选择 |

**图卡进来自动读三遍**，间隔 1.2 秒——听一遍学不会一个词，而且这个年纪不会自己想到"图片是个按钮"。中间的静默是留给孩子跟读的。翻页或退出这一页，剩下的遍数就不再响：排程只在图卡页推进。

手动重播（轻触或 A 键）**只读一遍**，并把排着的自动遍数丢掉——`audioPlay()` 是异步的且新请求会打断正在播的，不丢的话过一会儿自动那遍会盖住孩子刚要求的这遍。

轻触的响应区是**整个页面**，不是图片。图片在 466 px 屏上只有 144 px，占不到十分之一的玻璃，早先把点击挂在图片上，孩子照着猫去点，多半点在黑底上什么也没发生。

答题页的听音题**仍然只读一遍**：那里声音就是题目，读三遍会给每道题凭空加五秒。但**点卡片以外的任何地方都能重听**——声音既然是题目，漏听了就等于题目消失了，而先前那一页上除了两张答案卡没有任何可点的东西。看词选图题**没有重听**：写着的那个词才是题目，把它念出来等于把题型退回成听音题。

按键引导放在**各自按键的正下方**（`±95, -145`），不是并作一行摆在底部——按键像耳朵长在 10 点和 2 点方向，底部那行谁也没指。选组页的瓦片环为此整体**下移 30 px**：缩半径也能让开位置，但会把相邻瓦片的间隙从 17 px 挤到 7 px，八块糊成一团；下移正好搬进底部空出来的地方。

前 6 题是**听音选图**（只放声音，不出文字，不识字也能赢），后 4 题是**看词选图**（出英文，认字形）。答错不扣分、不显示红叉，只把正确那张描绿并把单词拼出来——图卡阶段没出现过的书面形式，第一次出现是在孩子刚证明自己听懂了之后。

## 内容：仓库存全量，固件只装一部分

词表 **480 词 / 40 组**，图片和音频**全部**抓好放在 `tools/english_pipeline/.cache/`（约 26 MB）并进版本库——换台电脑克隆下来就能直接构建，不需要任何外部输入也不需要联网。

但固件不必全装。`--pack-units N` 只把前 N 组打进 `english_data.bin`，缓存不动：

| 打包 | 词数 | blob | 固件 | factory 余量 |
|---|---|---|---|---|
| 16 组 | 192 | 2.86 MB | ~5.6 MB | 49% |
| **24 组（当前）** | **288** | **4.11 MB** | **7.00 MB** | **36%** |
| 40 组（全部） | 480 | 7.03 MB | ~10.0 MB | 9% |

换档位只要重跑管线加个参数，不用重新下载任何东西。

### blob 是链接进去的，不是编译进去的

早先 blob 走 C 数组。60 词时那是个 6 MB 的 .c 文件，只是难看；480 词时它是 **43 MB**，GCC 要几分钟才嚼得完，每次不相干的重编译都被拖累。

现在 `main/CMakeLists.txt` 用 `EMBED_FILES` 直接链接 `english_data.bin`，编译器根本看不到这些字节：构建从几分钟变成瞬间，仓库存 4 MB 而不是 43 MB。`english_data.h` 只是给链接器生成的符号起个固件用的名字。

## 已知缺口

- **音效槽是空的。** ENG1 格式和 `playSfxOrSpeak()` 都留好了动物叫声的位置（`Unit::has_sfx`），但还没接音源。现在一律回落到单词发音。「听声辨物」和「图片渐显猜词」两个玩法因此还没上。
- 单词字体复用拼音字体（只有小写 a-z），所以英文全小写显示。这个年龄段本来就该先认小写，但要显示 `I` 或专有名词得另生成字体。
- 一组的错词位掩码是 `uint32_t`，单元宽度上限 32 词。
- `AppEnglish::kMaxUnitsTracked = 64`：星级记录一组一字节。blob 组数超过它会拒绝打开而不是越界读（这里曾经是 `_best[8]`，词表一涨就成了越界读）。
- 单元选择环一页 8 格，`show()` 按选中项自动翻页。24 组要按 A 键翻 3 页，组数再多就该考虑分层了。
- `bored / scared / surprised` 三个词只有原形（`bore`/`scare`/`surprise`）的录音，静音出货。`logic_test` 的有声率断言因此放宽到 98% 并打印静音词。
