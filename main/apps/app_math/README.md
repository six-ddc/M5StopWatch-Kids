# AppMath — 100 以内加减法

给 6-7 岁小朋友的加减法闯关，跑在只有两个按键的圆屏手表上。

三层结构：**答题核心**（二选一 + 真实错解干扰项）、**局内节奏**（连对环、里程碑、第十题金星题）、**跨局经济**（星尘 → 星星 → 解锁新玩法 → 关卡地图）。核心答题机制刻意保持不变——游戏化全部长在它外面。

## 为什么是二选一

手表只有 A、B 两个键。输入 0~99 的数字要么靠滚轮（慢到孩子会烦），要么靠圆环键盘（70 px 的键，小手指按不准）。二选一把作答压成一次动作：**A 键选左卡、B 键选右卡，手指直接点也行**，没有光标、没有确认步骤、没有要学的东西。

代价是理论上有 50% 蒙对率。压制它的不是加题目，是三件事：

**干扰项都是真实错解，一个随机数都没有。** 每道题的错误选项从一个加权池里挑，池子里全是这个年龄段真会犯的错：

| 错解类型 | 例 | 权重 | 何时启用 |
|---|---|---|---|
| 忘进位 / 忘退位（±10） | `9 + 9 = 18` → `8` | 5 | **仅当真的进位或退位** |
| 个位反着减 | `15 - 8 = 7` → `13` | 5 | 仅退位减法 |
| 整十滑一档（±10 / ±20） | `80 - 40 = 40` → `30` | 5 / 1 | 仅两个操作数都是整十 |
| 加减号看反 | `36 - 7 = 29` → `43` | 4 | 总是 |
| 个位差一 | `27 + 15 = 42` → `41` | 各 2 | 非整十题 |
| 数位颠倒 | `42` → `24` | 1 | 结果两位数且个位非 0 |

**启用条件比错解类型本身更要紧。** 早期版本把 ±10 无差别套到所有档，于是出现 `9 - 1 = 8` 配干扰项 `10`——这题根本没有退位可忘，10 只是一个大于被减数的数，不用算就能排除。同理 `80 - 40 = 41`（整十减整十不可能出个位）和 `30` 数位颠倒成 `3`。这些不是"难一点的干扰项"，是**没有对应思维过程**的数字，白白送分。

反过来，`9 + 9 = 18` 配 `8` 位数都不一样，看着像能一眼排除，其实是全套里最有价值的一个——忘进位正是这一档最高频的错误，会犯的孩子就是会写 8。所以这里**不能**拿"干扰项要和答案位数相同"当验收标准，那会把最好的干扰项筛掉。

真正的标准是**每个干扰项都能归因到一个具体错误类型**。`math_logic_test` 每档采样 20 万道题反推分类，实测无法归因的比例是 **0.000%**：

```
tier                      carry   ones   tens   sign   off1   swap  unattr
10 以内加法            6.4%   0.0%   0.0%  26.9%  66.7%   0.0%   0.00%
10 以内减法            3.7%   4.8%   1.2%  47.1%  43.2%   0.0%   0.00%
20 以内进退位        38.8%  12.8%   0.0%  16.9%  28.0%   3.5%   0.00%
整十数加减            0.0%   0.0%  88.6%  11.4%   0.0%   0.0%   0.00%
两位数加减一位数  17.5%   7.0%   0.0%  32.6%  36.0%   6.9%   0.00%
两位数加减两位数  13.3%   6.2%   1.0%  24.7%  47.0%   7.8%   0.00%
```

（池子里所有候选都会被 0~99 边界过滤；万一全被过滤光，才会退到"答案 ±2~5"的随机兜底。实测从未发生，上表 `unattr` 一列就是它的触发率。）

两张卡都"看着像"，蒙不出来——想选对只能真算。反过来，孩子选了哪个错项也就说明了他卡在哪一步。

**连对会被清零。** 进度环的颜色跟着连对数走（蓝 → 青 → 金），错一次归零。蒙的期望收益远低于算。

**错题会回来。** 一关十道，答错的题在关末重出一遍，换一个干扰项、换左右位置——第二次答对必须是真算出来的，不能靠记住"上次点的是右边"。

正确答案落在左边还是右边每题各 50% 随机，防止孩子形成固定按键习惯。

## 难度

六档，按一年级课程推进的顺序排。第三档是真正的难点，前两档是热身，后三档是同一个技能换更大的数：

1. 10 以内加法 · 2. 10 以内减法 · 3. **20 以内进位加 / 退位减** · 4. 整十数加减 · 5. 两位数 ± 一位数 · 6. 两位数 ± 两位数

不变量（全部由 `tools/math_host_test` 断言）：结果恒在 0~99，减法保证被减数 ≥ 减数（这个年纪还没学负数），不出 `+0` / `-0`，最近 8 道题不重复。第三档还额外保证加法真的进位、减法真的退位——不进位的 `3 + 4` 混进这一档就白练了。

**自适应**：一关十道里答对 ≥ 8 且最长连对 ≥ 5 就升一档；答对 < 5 降一档。两个条件都要满足才升，因为"答对 8 道但错得零零散散"和"连着对 8 道"是两种完全不同的掌握程度。

**地图**：六档摆成绕屏一圈的六个节点（圆屏自己就是路径），孩子在地图上选关。已解锁范围 = 自适应曾经推荐到过的最高档（`maxtier`，对老存档回退为当前档），已解锁的关随便重玩——回头刷低档也是练习，不拦。自适应从"替孩子换档"降级成"选中推荐的下一档"：选择权在孩子手里，自己选的关，输了也更愿意再来。开屏进地图；结算页 A 直接再来一关、B 回地图。锁着的节点是风景，点了没反应。

**金星题**：每关第十题，状态行金字标出，走 `Generator::nextGold`——同一套 build 规则里优先挑会进/退位的形态。这个"最难形态"在低档位上恰好落在边界技能上：10 以内加法的金星题是凑十（和恰为 10），10 以内减法是 10 - x；整十档不存在进退位，重采样全部落空、自动退化成普通题——金星题的加成给的是仪式感，不造假难度。答对多得 1 星尘。

**判断题（对不对）**：攒到 10 ⭐ 解锁的变奏，每关随机混入 2 道（不占金星位）。屏上显示完整算式 `27 + 15 = 41`，左卡永远是"对"、右卡永远是"错"——内容在变，按键语义就必须不变。展示的数值复用 Pick 的干扰项机制：假算式永远是一个"真会犯的错"，不能靠离谱程度识破。实现上一个字段都没加：`answer_on_left` 语义变成"算式为真"，左卡（对）该选当且仅当算式为真，`submit()` 根本不需要知道题型。错题重出时 reroll 会换掉展示值、可能翻转真假——照样成立。

## 星尘经济

单一货币两个面额：**10 星尘（✦）= 1 星星（⭐）**。汇率不是随便选的——钱包本身就是一个会进位的两位数，孩子每次看余额都在复习"满十进一"，结算页星尘凑满十颗收成一颗星的那一下，配的就是进位专属音效和星星脉冲。

| 事件 | 奖励 |
|---|---|
| 首答对 | +1 ✦ |
| 错题重做答对 | +1 ✦ |
| 金星题答对 | 额外 +1 ✦ |
| 关末星级（只看首答） | +0~3 ⭐ |

**星尘酬劳努力，星星酬劳掌握**，这个拆分是刻意的：星级继续只认首答，自适应难度的判断不受污染；但错得多的孩子（最需要鼓励的）每关也有 5~8 ✦ 落袋。旧方案里星星只看 `fresh_correct`，激励结构正好反着——最挣扎的人拿到的最少。

一关星尘上界 11（每道题最多付一次 + 金星加成），`settle()` 是精确的十进制进位并在 65535 封顶——溢出回绕会把孩子攒的一切清零，这是这个系统唯一不许发生的事故。全部规则在 `game/economy.{h,cpp}` 纯逻辑层，host 测试断言收益上下界、进位守恒、解锁单调。

**解锁的奖品是玩法本身**：10 ⭐ 解锁判断题。外在奖励和内在动机指向同一处，星星才不会反过来淹没"好玩"。解锁瞬间（结算入账跨过门槛那一刻）全屏庆祝页直接把新玩法演出来——两张对/错卡——而不是用文字描述它。门槛表只 gate 已经实现的内容。

## 分层

```
game/problem.{h,cpp}    题目与干扰项生成、金星题、判断题   纯逻辑，无 LVGL / 无 ESP-IDF
game/session.{h,cpp}    关卡、连击、错题队列、星级、混入   同上
game/economy.{h,cpp}    星尘/星星钱包、收益规则、解锁门槛   同上
view/quiz.cpp           答题页
view/result.cpp         结算页 + 解锁覆盖页
view/map.cpp            关卡地图
app_math.{h,cpp}        生命周期、按键、反馈与庆祝时间线、NVS
```

`game/` 两层完全不碰平台头文件，所以能在主机上以每秒百万道的速度跑断言。随机数用内置的 xorshift 而不是 `esp_random()`：固件开机时用硬件熵播种，主机测试给固定种子，**同一个种子的题目序列逐位可复现**。

## 布局：跟着按键走

两个按键长在表壳上，像耳朵一样位于 **10 点和 2 点方向**（距正上方约 ±41°）。答案卡就放在它们**正下方**，而不是排在屏幕底部——这样"按左边的耳朵"和"选左边那张卡"在空间上是同一个动作，不只是名字上对应。这是二选一玩法适配这个硬件的全部理由，卡片位置对不上，这份优势就丢了一半。

屏幕是圆的，可视半径 233 px。所有坐标相对屏幕中心：

```
          A 键↖                ↗B 键          表壳上 ±41°
        ╭────────────────────╮
      ╱  ┌──────┐    ┌──────┐  ╲   150×92，中心 (±88, -95)
     │   │  42  │    │  32  │   │   64 px，正对按键
     │   └──────┘    └──────┘   │
     │                         │
     │        27 + 15          │   y=+30   96 px
     │                         │
      ╲     4/10 · 连对 3      ╱   y=+150  24 px
        ╰────────────────────╯
        外圈进度环 r=220 w=10，颜色跟连对走
```

**读的顺序是"选项在上、题目在中"，看着反了，实际不是。** 算式 96 px 且居中，视线一定先落在它上面——视觉层级比垂直顺序更强。真按从上到下排（题在上、卡在下），卡片就离按键更远了，而且圆屏下半部会空出一大块、整体头重脚轻。

卡片外角落在距圆心 215 px 处（可视半径 233）。进度用外圈弧而不是中间的圆点条：只在边缘发光，屏幕中央保持全黑。

结算页同理，`A 再来一关` 和 `B 地图` 分别摆在各自按键下方，而不是挤在底部一行；地图页则是 `A 换一关`、`B 开始`。

**答对后算式不会补成 `27 + 15 = 42`。** 生成器能出的最宽算式是 `50 + 40`，96 px 下 358 px——它来自整十数档而不是两位数档，因为 `0` 的字形比 `8`、`9` 都宽，而这一档每个数都带 0。补全成 `50 + 40 = 90` 要 **600 px**，屏幕总共才 466 px 宽。要塞下得把字压到 50 px 出头，跟"超大字"的初衷正好相反。何况答案本来就印在卡片上、还会被描绿，再写一遍是重复。所以反馈只改算式的**颜色**。

上面这些宽度全是 `math_sim` 量出来的，不是推出来的。**最宽的算式由生成器自己交出**：sim 采样每一档二十万道题，逐个测渲染宽度取最大。手挑一个"看着最宽"的字符串行不通——第一版挑的是 `88 + 99`，看着很宽，但和超过 99、生成器永远不会出这道题。拿不可能出现的输入测布局，比不测更糟，因为它给的是假的安全感。

越界本身也不是靠肉眼看截图发现的，是 `math_sim` 断言"任何点亮的像素都不许落在 r=233 之外"抓出来的。它还抓到过结算页的 `A` / `B` 显示成 □——字体子集当时只有小写字母。

## 反馈

| | 视觉 | 音效 | 震动 | 停顿 |
|---|---|---|---|---|
| 答对 | 选中卡描绿，算式转绿 | 上扬两音，**随连对沿大调音级整体升调** | 20 ms（60%） | 600 ms |
| 连对跨过 3 / 5 | 环当场变色 + 单次辉光脉冲 | 升调三音（补全三和弦） | 25 ms × 2，隔 80 ms | 600 ms |
| 错题重做答对 | 同答对 | 三音上行解决式 | 20 ms（60%） | 600 ms |
| 答错 | 选中卡描红，**同时把正确那张也描绿** | 下行两音，**永不变化** | 40 ms | 1500 ms |

答对音从连对 1 的 `{72,76}` 沿大调音级爬升，连对 8 封顶在 +12——正好一个八度，而 8 也是升档门槛："爬到顶了"和"该升级了"是同一个声音。答错音永远是那两个下行音：失败反馈绝不许变得好玩，否则孩子会故意答错去收集音效。

环变色原来发生在下一题刷新时，静悄悄的；现在挪到跨过里程碑的那次反馈里，配唯一一次脉冲和双震——里程碑得是孩子看得见的事件。双震的第二下由 `onRunning` 在冻结时间线里补，不阻塞。

停顿期间按键和触摸全部吞掉，期间按下的也不排队——这段时间存在的意义就是让孩子看清正确答案，让他一按就跳过等于没有。答错给两倍多的时间，因为那才是有东西要读的时候。判断题答错时算式会改写成正确等式并转绿：假算式被识破（或没识破）之后，孩子该读的正是那一行真话。

**答题中静止，庆祝时刻放开**：题目在屏上时只有静态配色（这块屏是给小孩长时间盯着看的），一次性脉冲只出现在里程碑；结算页才是动画的主场——星星逐颗落下（每颗一声升调 + 一次轻震）、星尘逐点入账、凑满十颗进位成星。庆祝全程 < 3 秒，第一颗星落下后任意按键点按快进到最终画面，**快进不会误开下一关**（结算页有独立的庆祝中状态）。序列由 app 层时间线驱动而不是 LVGL 动画链，因为每一步都要在锁外发声。

## 线程纪律

沿用识字 App 那套（都是在这台机器上踩出来的）：

- **触摸回调只置一个标志位**。回调跑在 `lv_timer_handler` 里、LVGL 锁已经被持有，所以回调里不能再 `lvglLock()`（`xGuiSemaphore` 非递归，会死锁），也不能写 NVS。实际处理放回 `onRunning`。
- **NVS 只在关卡结束时写**。写 flash 会关掉 cache 并挂起另一个核。
- **按键轮询节流到 40 Hz**。每次轮询是一笔 I2C 事务，主循环转得比人按键快几个数量级。
- **音频合成在锁外**。`play_melody` 要建 PCM 缓冲。
